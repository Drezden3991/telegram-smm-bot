# SMM Bot MVP — Правила проекта

Дата создания: 05.07.2026

---

# Главный принцип

Мы создаём не учебный пример, а настоящий коммерческий продукт.

Во время разработки главное — получить рабочий результат.

Обучение происходит отдельно.

---

# Правила разработки

## 1. Финальная версия

Во время разработки раздела пишется сразу финальная рабочая версия.

Промежуточные версии создаются позже во время изучения проекта.

---

## 2. История версий

Для каждого раздела заранее создаются названия будущих версий в `code_history`.

Код этих версий можно написать позже.

---

## 3. Документация

Перед началом нового этапа всегда обновляется документация проекта.

Используем:

- ROADMAP.md
- PROJECT_LOG.md
- BACKLOG.md
- LEARN_LATER.md
- CHANGELOG
- code_history

---

## 4. CHANGELOG

CHANGELOG показывает развитие конкретного раздела.

Каждая версия описывает изменения относительно предыдущей.

---

## 5. PROJECT_LOG

PROJECT_LOG содержит только завершённые версии всего проекта.

---

## 6. BACKLOG

BACKLOG содержит идеи, которые пока не реализованы.

Любая новая идея сначала записывается туда.

---

## 7. LEARN_LATER

Если во время разработки появляется новая тема Python или aiogram, которую пока рано изучать, она записывается в LEARN_LATER.

---

## 8. CLIENT_FEEDBACK

Все предложения заказчика записываются отдельно.

После анализа они либо:

- переходят в BACKLOG;
- либо становятся новой версией проекта.

---

# Работа с кодом

## 9. Один раздел — один файл

Каждый раздел главного меню находится в отдельном файле папки handlers.

---

## 10. Один раздел — одна история

Каждый раздел имеет собственную папку `code_history`.

История развития каждого раздела хранится отдельно.

---

## 11. Простота кода

Если существует несколько вариантов реализации, выбирается самый понятный для новичка.

---

## 12. Минимизация новых концепций

За одно занятие желательно использовать только один новый концепт Python.

---

## 13. Минимизация сообщений

Если изменяется один файл, работаем только с ним.

Не переписываем весь проект без необходимости.

---

## 14. Архитектурные улучшения

Во время MVP не усложняем архитектуру.

Все технические улучшения откладываются до отдельного этапа проекта.

Например:

- utils
- SQLite
- уникальный ID
- рефакторинг

---

# Процесс разработки

Работа над разделом проходит так:

ROADMAP

↓

План версий

↓

Финальная версия раздела

↓

CHANGELOG

↓

PROJECT_LOG

↓

BACKLOG (при необходимости)

↓

Следующий раздел

---

# Обучение

После завершения MVP начинается отдельный этап обучения.

Тогда постепенно восстанавливается эволюция проекта:

v0.1

↓

v0.2

↓

v0.3

↓

...

↓

v1.0

и подробно разбирается код каждой версии.

---

# Версионирование

Основные версии:

- v0.1
- v0.2
- v0.3
- ...
- v1.0

используются для нового функционала.

Подверсии:

- v0.2.1
- v0.3.1
- v1.0.1

используются для:

- исправления ошибок;
- небольших улучшений;
- архитектурных изменений.

---

# Главная цель проекта

Создать коммерческий Telegram-бот для помощи SMM-специалистам.

Не пытаться сделать идеальный продукт сразу.

Развивать проект маленькими шагами.

Каждая новая версия делает продукт лучше предыдущей.
