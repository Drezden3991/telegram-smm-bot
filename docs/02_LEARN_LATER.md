# Подход к изучению проекта

## Как разбирать SMM Bot после возвращения к обучению

Не пытаться изучить весь проект одновременно.

Предпочтительный порядок:

1. базовые конструкции Python;
2. функции, списки, словари и исключения;
3. файлы и JSON;
4. async / await;
5. aiogram;
6. Router / handlers / filters;
7. FSM;
8. архитектура handlers / services / storage / models;
9. SQLite и базовый SQL;
10. миграции и устойчивые ID;
11. multi-user ownership;
12. тестирование;
13. Git;
14. API и SDK;
15. Pydantic;
16. AI providers;
17. Structured Outputs / JSON Schema;
18. Redis и persistent FSM;
19. logging и error handling;
20. backups;
21. security/privacy basics;
22. Linux / systemd / deployment;
23. health checks и production smoke-tests;
24. только затем переходить к Web/API и следующим большим этапам проекта.

Главный принцип:

**изучать по одной новой концепции за раз и сразу находить её применение в реальном коде SMM Bot.**

Не пытаться выучить весь файл LEARN_LATER подряд.

Использовать его как карту тем, к которым нужно постепенно возвращаться.

Особенно при изучении Stage 5:

**сначала понять простую идею → затем открыть конкретный файл проекта → затем самостоятельно объяснить, зачем этот код существует → только после этого переходить к следующей теме.**
