# PROJECT ROADMAP — SMM Bot MVP

Дата обновления: 04.08.2026

---

# Общая цель проекта

Создать Telegram-бота для SMM-задач:

- управление клиентами;
- хранение идей постов;
- создание и хранение постов;
- создание AI-контент-планов;
- подготовка проекта к реальному использованию.

Основной принцип разработки:

- сначала завершить рабочий MVP;
- затем улучшать архитектуру;
- новые функции добавлять только после оценки пользы;
- сложные изменения выполнять небольшими проверяемыми шагами.

# Архитектура v2.5

Цель:

Разделить ответственность внутри проекта:

handlers
    ↓
services
    ↓
storage
models


---

## Ответственность слоёв

### handlers

Отвечают только за:

- Telegram;
- сообщения;
- клавиатуры;
- FSM;
- пользовательские сценарии.

---

### services

Отвечают за:

- бизнес-логику;
- правила работы данных;
- поиск;
- проверки;
- обработку операций.

Не зависят от aiogram.

---

### storage

Отвечает за:

- чтение данных;
- сохранение данных;
- преобразование форматов.

Не содержит бизнес-правил.

---

### models

Отвечает за:

- структуры данных;
- модели объектов.

---

# Текущие ограничения проекта

- Данные хранятся в локальных файлах.
- Нет базы данных.
- Нет миграций.
- Нет уникальных ID для всех сущностей.
- Возможны проблемы при одинаковых именах клиентов.
- Нет пагинации больших списков.
- FSM использует временное хранение.
- Нет публичного деплоя.
- Нет production-мониторинга.
- Посты создаются по шаблонам.
- Нет AI-генерации постов.
- Нет полноценного коммерческого использования.

# Принцип развития

Каждая версия должна быть:

- законченной;
- проверяемой;
- ограниченной по области изменений.

Перед крупными изменениями:

- сохранить рабочую версию;
- обновить документацию;
- проверить тесты.

После изменений:

- автоматические тесты;
- компиляция;
- `git diff --check`;
- ручной smoke test;
- проверка ошибок;
- проверка сохранения данных.

После успешной проверки:

- обновить CHANGELOG;
- обновить документацию;
- создать Git-коммит;
- отправить изменения на GitHub.
