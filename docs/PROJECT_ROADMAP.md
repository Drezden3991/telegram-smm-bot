# SMM Bot — Project Roadmap

Дата создания: 03.07.2026  
Последнее обновление: 02.08.2026

---

# Цель проекта

Создать коммерческий Telegram-бот для помощи SMM-специалистам: вести клиентов, хранить идеи, готовить посты и создавать контент-планы.

Проект развивается законченными версиями. Базовый MVP завершён.

Текущий активный этап — этап 2 «Интеграция разделов».

Во время OpenAI Build Week 2026 вне основного порядка была добавлена первая AI-функция — генерация семидневного контент-плана через OpenAI API. После конкурса проект вернулся к основному порядку разработки.

До этапа 4 новые AI-функции не добавляются. Разрешены только исправления ошибок, обеспечение безопасности и совместимости уже реализованного AI-контент-плана.

# Этап 1 — Базовый MVP

Статус: ✅ Завершён

## 👥 Клиенты — v1.0

Реализованы:

- добавление клиента;
- просмотр списка;
- карточка клиента;
- поиск;
- редактирование;
- удаление;
- проверка дубликатов.

Карточка клиента содержит:

- имя;
- фамилию;
- телефон;
- Instagram;
- email;
- заметки.

Данные хранятся в `clients.txt`.

## 💡 Идеи постов — v1.0

Реализованы:

- добавление идеи;
- просмотр списка;
- случайная идея;
- поиск;
- редактирование;
- удаление;
- проверка дубликатов.

Данные хранятся в `post_ideas.txt`.

## ✍️ Написать пост — базовый MVP v1.0

Реализованы:

- создание шаблонного поста;
- ввод клиента;
- выбор темы или идеи;
- выбор стиля;
- сохранение;
- история постов;
- поиск;
- удаление по ID.

Данные сохраняются в JSON-файл `posts.txt`.

## 📅 Контент-план — базовый MVP v1.0

Реализованы:

- создание статического плана по теме;
- сохранение;
- просмотр;
- поиск;
- редактирование;
- удаление.

Сценарии используют aiogram FSM. Данные хранятся в `content_plans.txt`.

# Текущие ограничения

- Данные хранятся в локальных TXT- и JSON-файлах.
- Нет базы данных и миграций.
- Нет пользовательской изоляции.
- Нет уникальных ID клиентов и идей.
- При одинаковых именах клиентов возможна неоднозначность.
- При большом количестве клиентов и идей динамические клавиатуры станут слишком длинными.
- Нет пагинации.
- Часть раздела «Клиенты» использует глобальные переменные состояния.
- Нет полноценного автоматизированного тестового набора для всех разделов.
- Посты создаются по статическим шаблонам.
- Идеи постов не генерируются через AI.
- Сохранённые идеи пока не используются при создании контент-плана.
- Нет публичного деплоя.
- Бот работает только при запущенном локальном процессе Python.
- Нет production-мониторинга и журналирования.

# Принцип развития

Каждая основная версия должна быть законченной, проверяемой и ограниченной по области изменений.

Во время основной разработки создаётся финальная рабочая версия раздела. Промежуточные версии могут быть заранее запланированы в `code_history`, но их код восстанавливается позже во время отдельных учебных сессий.

Перед крупным изменением предыдущая рабочая версия должна быть сохранена в `code_history`.

После создания нового или существенно обновлённого кода обязательно выполняется ручная проверка:

- основной сценарий;
- альтернативные варианты;
- неправильный ввод;
- пустые данные;
- переходы «Назад»;
- сохранение результата;
- поиск;
- редактирование;
- удаление, если оно предусмотрено.

После успешной проверки:

- версия сохраняется в `code_history`;
- обновляется разделовый `CHANGELOG.md`;
- изменения фиксируются отдельным Git-коммитом;
- коммит отправляется на GitHub.

Новые AI-функции добавляются только на этапе 4 и не должны ломать существующие CRUD-сценарии или сохранять неполный результат.
