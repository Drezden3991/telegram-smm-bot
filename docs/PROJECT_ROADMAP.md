# Общая цель проекта

Создать Telegram-бота для SMM-задач:

- управление клиентами;
- хранение идей постов;
- создание и хранение постов;
- создание AI-контент-планов;
- AI-генерация идей постов;
- AI-генерация готовых постов;
- подготовка проекта к реальному использованию.

Основной принцип разработки:

- сначала завершить рабочий MVP;
- затем улучшать архитектуру;
- новые функции добавлять только после оценки пользы;
- сложные изменения выполнять небольшими проверяемыми шагами;
- не расширять scope текущего этапа без необходимости.

# Архитектура v2.5

Цель:

Разделить ответственность внутри проекта:

handlers
    ↓
services
    ↓
storage

services ← models
storage  ← models

---

## Ответственность слоёв

### handlers

Отвечают только за:

- Telegram;
- сообщения;
- клавиатуры;
- FSM;
- пользовательские сценарии.

---

### services

Отвечают за:

- бизнес-логику;
- правила работы данных;
- поиск;
- проверки;
- обработку операций;
- подготовку безопасного AI-контекста;
- orchestration AI-сценариев.

Не должны смешивать Telegram/UI с основной бизнес-логикой.

---

### storage

Отвечает за:

- чтение данных;
- сохранение данных;
- parsing;
- serialization;
- преобразование файловых форматов.

Не содержит бизнес-правил.

---

### models

Отвечает за:

- структуры данных;
- модели объектов;
- Pydantic-схемы структурированных AI-ответов.

- невозможность надёжно решить общую семантическую задачу детерминированными правилами.

Решение:

Сохранить:

- Structured Outputs;
- Pydantic-валидацию;
- человеческую проверку.
