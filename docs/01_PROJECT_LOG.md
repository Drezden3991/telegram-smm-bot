# Итоговая техническая проверка этапа 2

После завершения основных интеграций Codex выполнил отдельную итоговую проверку взаимодействия четырёх разделов:

- «Клиенты»;
- «Идеи постов»;
- «Написать пост»;
- «Контент-план».

## Найденные проблемы

Во время проверки были подтверждены шесть проблем:

1. Кнопка `⬅️ Назад` не обрабатывалась отдельно в FSM раздела идей.
2. Общие обработчики `Назад` конфликтовали с клиентскими сценариями.
3. Клиентские состояния хранились в глобальных переменных.
4. Команда `/start` не очищала активный FSM-сценарий.
5. Устаревший номер идеи мог вызвать `IndexError`.
6. Номера идей контент-плана не были привязаны к показанному пользователю списку.

## Выполненные исправления

### Раздел «Идеи постов»

Добавлена отдельная обработка `⬅️ Назад` для:

- добавления идеи;
- выбора номера для редактирования;
- ввода нового текста;
- выбора номера для удаления;
- поиска.

Кнопка больше не сохраняется как:

- новая идея;
- новый текст идеи;
- поисковый запрос;
- некорректный номер.

### Раздел «Клиенты»

Глобальные флаги и временные переменные заменены на FSM-группу `ClientFlow`.

Теперь:

- состояние хранится отдельно для каждого пользователя;
- временные данные пользователей не смешиваются;
- завершение очищает FSM;
- отмена очищает FSM;
- возврат назад очищает или изменяет состояние корректно;
- общие обработчики других роутеров не перехватывают клиентский сценарий.

### Команда `/start`

Обработчик `/start` теперь:

- принимает `FSMContext`;
- очищает активное состояние;
- удаляет временные данные незавершённого сценария;
- после этого показывает главное меню.

### Защита редактирования идеи

При выборе идеи сохраняются:

- номер;
- точный текст выбранной записи.

Перед изменением:

- список загружается повторно;
- проверяется существование выбранной записи;
- проверяется соответствие сохранённому снимку;
- другая идея не изменяется;
- `IndexError` не возникает.

### Снимок списка идей контент-плана

Контент-план сохраняет в FSM список идей, который был показан пользователю.

Номера относятся именно к этому снимку.

Выбранные идеи проверяются:

- при нажатии номера;
- при завершении выбора;
- перед AI-генерацией;
- после AI-генерации перед сохранением.

Изменение порядка или содержимого файла не приводит к выбору другой идеи.

# Текущие ограничения

- Данные хранятся в TXT- и JSON-файлах.
- Нет SQLite.
- Нет пользовательских профилей.
- Нет постоянной изоляции файловых данных разных пользователей.
- Нет уникальных ID клиентов и идей.
- При одинаковых именах клиентов возможна неоднозначность.
- Динамические клавиатуры не имеют пагинации.
- При большом количестве клиентов и идей клавиатуры станут слишком длинными.
- FSM хранит незавершённые состояния в памяти.
- Незавершённые состояния теряются после перезапуска бота.
- Автоматические тесты пока не покрывают весь проект одинаково подробно.
- Тексты постов создаются по статическим шаблонам.
- AI-генерация постов не реализована.
- AI-генерация идей не реализована.
- Нет публичного деплоя.
- Бот работает только при запущенном локальном процессе Python.
- Нет production-мониторинга и журналирования.
- Интерфейс ещё не прошёл полноценную проверку заказчицей.

# Правило проверки нового кода

После каждого нового или существенно обновлённого кода выполняются автоматические и ручные проверки.

Автоматически проверяются:

- существующие тесты;
- новые тесты изменённого поведения;
- компиляция;
- `git diff --check`;
- отсутствие реальных AI-запросов в тестах.

Вручную проверяются:

- основной сценарий;
- альтернативные варианты;
- пустые данные;
- неправильный ввод;
- переходы `⬅️ Назад`;
- команда `/start`;
- сохранение;
- просмотр;
- поиск;
- редактирование;
- удаление, если оно предусмотрено;
- отсутствие конфликтов между разделами.

Пользователь выполняет короткий smoke test после завершения рабочего блока.

Полноценная оценка:

- удобства интерфейса;
- понятности сценариев;
- практической пользы;
- качества результата;

проводится заказчицей по отдельному списку заданий.

Только после успешной проверки:

- версия сохраняется в `code_history`;
- обновляется разделовый `CHANGELOG.md`;
- обновляется проектная документация;
- создаётся отдельный Git-коммит;
- коммит отправляется на GitHub.
