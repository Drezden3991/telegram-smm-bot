# Активные задачи

## Архитектура v2.5

Статус: ⬜ Запланировано

Приоритет: Высокий


Цель:

Создать устойчивую структуру проекта:

handlers
    ↓
services
    ↓
storage
services ← models
storage  ← models


Ответственность:

### handlers

Только:

- Telegram;
- сообщения;
- клавиатуры;
- FSM;
- пользовательские сценарии.

### services

Только:

- бизнес-логика;
- правила работы данных;
- проверки;
- операции над сущностями.

### storage

Только:

- чтение данных;
- сохранение данных;
- преобразование форматов.

### models

Только:

- структуры данных;
- модели объектов.

# Правила BACKLOG

BACKLOG используется для:

- сохранения будущих идей;
- фиксации технического долга;
- планирования следующих этапов.


Не используется для:

- срочного добавления новых функций;
- расширения текущего этапа без оценки;
- преждевременной универсализации.


Каждая новая задача оценивается:

- делает ли она продукт лучше;
- нужна ли она текущему этапу;
- не создаёт ли лишний технический долг.
