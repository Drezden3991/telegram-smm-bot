- защита от устаревших номеров и изменившихся списков;
- итоговая техническая проверка интеграции;
- добавление интеграционных тестов.

Во время OpenAI Build Week 2026 вне основного порядка были выполнены отдельные опережающие изменения:

- добавлена AI-генерация контент-плана;
- подключён Git;
- проект опубликован на GitHub;
- к репозиторию подключён Codex.

Эти изменения не означают завершение этапов архитектурного улучшения, полного внедрения AI или коммерческой подготовки проекта.

Дальнейшее расширение AI отложено до этапа 4.

До этого разрешены:

- критические исправления;
- устранение угроз безопасности;

# Обновление aiogram

Текущая версия:

``text
aiogram 3.29.1

После стабилизации первой версии:
изучить актуальную стабильную версию;
сравнить изменения;
оценить необходимость обновления;
проверить совместимость;
задокументировать изменения.
Правило использования Codex
Codex используется для задач, требующих работы непосредственно с репозиторием:
изучение нескольких файлов;
реализация согласованных изменений;
поиск ошибок;
ограниченный рефакторинг;
запуск тестов;
проверка безопасности;
ревью перед коммитом.
Codex не должен:
менять архитектуру без согласования;
расширять задачу;
переходить на следующий этап ROADMAP;
добавлять новые функции без решения;
выполнять реальные OpenAI-запросы в тестах.
Правило ведения code_history
Перед крупным изменением предыдущая рабочая версия сохраняется в code_history.
Каждая сохранённая версия содержит:
что нового относительно предыдущей версии;
что умеет версия;
текущие ограничения;
почему версия сохранена.
Git используется как фактическая история изменений проекта.
code_history используется как учебная история развития кода.
Общее правило проекта
До завершения текущего этапа не выполнять крупные изменения, которые не относятся к текущей задаче.
Архитектурные идеи фиксируются в BACKLOG и реализуются только в соответствующий этап.
Каждая новая функция оценивается:
Делает ли она работу пользователя проще, быстрее, безопаснее или качественнее?

Если нет — задача остаётся в BACKLOG.
Не каждое пожелание заказчицы автоматически становится задачей разработки.
Обратная связь оценивается по:
реальной пользе;
частоте сценария;
влиянию на удобство;
риску ошибки;
стоимости реализации;
соответствию ROADMAP.
