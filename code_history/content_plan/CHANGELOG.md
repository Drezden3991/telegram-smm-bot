## v1.1 — AI-генератор семидневного контент-плана

### Что нового относительно v1.0

- Статический шаблон заменён AI-генерацией.
- Подключён OpenAI Responses API.
- Используется модель `gpt-5.6`.
- Добавлен `reasoning.effort="low"`.
- Добавлены Structured Outputs на основе Pydantic.
- План теперь состоит ровно из семи дней.
- Для каждого дня создаются:
  - номер дня;
  - цель;
  - тема;
  - формат;
  - ключевой тезис;
  - CTA.
- Добавлен единый краткий SMM-бриф.
- Добавлено ограничение брифа до 500 символов.
- Добавлена проверка порядка дней от 1 до 7.
- Синхронный вызов SDK запускается через `asyncio.to_thread`.
- Добавлено безопасное сохранение только полного валидного результата.
- Редактирование регенерирует выбранный план через тот же AI-контракт.
- Добавлено разделение длинных сообщений для Telegram.
- Добавлена обработка ошибок:
  - авторизации;
  - лимита запросов;
  - соединения;
  - тайм-аута;
  - ошибки сервиса;
  - неверной структуры ответа.

### Что умеет

- Принимать краткий свободный SMM-бриф.
- Генерировать семидневный контент-план.
- Проверять структуру результата.
- Форматировать план для Telegram.
- Сохранять только корректный результат.
- Показывать сохранённые планы.
- Искать планы.
- Редактировать планы через повторную AI-генерацию.
- Удалять планы.
- Отправлять длинные сообщения частями.

### Выполненные проверки

- Проверена компиляция обработчика.
- Проверена совместимость OpenAI SDK.
- Проверена Pydantic-схема.
- Проверена структура семи дней.
- Проверено форматирование Telegram-сообщения.
- Проверено отсутствие сохранения при ошибке API.
- Выполнен ручной live smoke test через Telegram 19.07.2026:
  - OpenAI вернул семь структурированных дней;
  - результат был показан в Telegram;
  - план был сохранён;
  - сохранённый план появился в списке.

### Ограничения

- Клиент не выбирается из сохранённого списка.
- Карточка клиента не используется как AI-контекст.
- Пользователь должен вручную описывать всю информацию о бизнесе.
- План не связан с другими разделами проекта.
- Хранение остаётся файловым.
- Нет уникальных ID контент-планов.

### Почему версия сохранена

- Это первая полноценная AI-функция проекта.
- Версия была создана во время OpenAI Build Week 2026.
- Она является последней рабочей версией до интеграции с разделом «Клиенты».

## v2.0 — integrated_content_plan_manager

Имя сохранённого файла:

`content_plan_v2_0_integrated_content_plan_manager.py`

### Что нового относительно v1.1

- Выполнена интеграция разделов «Клиенты» и «Контент-план».
- Перед созданием плана пользователь выбирает клиента кнопкой.
- Добавлен вариант «🚫 Без клиента».
- В кнопке клиента показываются имя и фамилия.
- Добавлено преобразование строки клиента из `clients.txt` в словарь.
- Карточка клиента автоматически используется как часть AI-брифа.
- В OpenAI передаются только подходящие для SMM данные:
  - имя клиента;
  - Instagram;
  - заметки.
- Телефон и email клиента в OpenAI не отправляются.
- Пользователь дополнительно вводит цель и особенности конкретного плана.
- Имя клиента сохраняется в готовом тексте контент-плана.
- Поиск теперь позволяет находить план по имени клиента.
- При редактировании можно заново выбрать клиента.
- Добавлены отдельные FSM-состояния:
  - выбор клиента для нового плана;
  - ввод брифа;
  - выбор клиента при редактировании;
  - ввод нового брифа.
- Добавлены переходы «⬅️ Назад» между этапами.
- Добавлена обработка пустого списка клиентов.
- Добавлена проверка неправильного выбора клиента.
- Сохранена существующая AI-генерация GPT-5.6.
- Сохранены поиск, просмотр, редактирование и удаление.
- Сохранено безопасное поведение при ошибках OpenAI.
- Длинные сообщения продолжают отправляться частями.

### Что умеет

- Открывать раздел «Контент-план».
- Создавать новый AI-контент-план.
- Загружать клиентов из `clients.txt`.
- Показывать клиентов кнопками.
- Выбирать сохранённого клиента.
- Создавать план без клиента.
- Использовать карточку клиента как AI-контекст.
- Принимать дополнительный пользовательский бриф.
- Генерировать ровно семь дней.
- Проверять структуру результата.
- Сохранять имя клиента в тексте плана.
- Сохранять план в `content_plans.txt`.
- Показывать все сохранённые планы.
- Искать планы по:
  - имени клиента;
  - теме;
  - брифу;
  - тексту плана.
- Редактировать сохранённый план.
- При редактировании заново выбирать клиента.
- Удалять план по номеру.
- Отправлять длинные сообщения частями.
- Возвращаться назад между этапами.
- Обрабатывать неправильный ввод.

### Выполненная ручная проверка

- Бот успешно запускается.
- Раздел «Контент-план» открывается.
- Сохранённый клиент выбирается кнопкой.
- Краткий бриф принимается.
- GPT-5.6 создаёт семидневный план.
- В готовом плане показывается имя клиента.
- План сохраняется в `content_plans.txt`.
- План отображается в списке.
- Создание через «🚫 Без клиента» работает.
- Поиск по имени клиента работает.
- Редактирование плана работает.
- Выбор клиента при редактировании работает.
- Удаление плана работает.
- Переходы «⬅️ Назад» работают.
- Во время выполненной проверки ошибок не обнаружено.

### Ограничения

- Контент-планы хранятся как большие текстовые блоки.
- Нет структурированного JSON-хранилища для готовых планов.
- Нет базы данных.
- Нет уникальных ID клиентов и контент-планов.
- При одинаковых именах клиентов возможна неоднозначность.
- Динамическая клавиатура клиентов не имеет пагинации.
- При большом количестве клиентов клавиатура станет слишком длинной.
- Изменение карточки клиента не обновляет уже сохранённые планы.
- Сохранённый план не хранит отдельную копию полной карточки клиента.
- Нет разделения данных между пользователями Telegram.
- Нет связи контент-плана с конкретными сохранёнными идеями постов.
- Дополнительное расширение AI-функций отложено до этапа 4.

### Почему версия сохранена

- Эта версия завершает интеграцию разделов «Клиенты» и «Контент-план».
- Она является итоговой рабочей версией раздела на этапе 2.
- Она сохраняет уже реализованную AI-функцию без расширения её области.
- Она создаёт основу для будущего перехода к структурированному хранилищу.
